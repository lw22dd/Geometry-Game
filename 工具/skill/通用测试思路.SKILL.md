# General Testing Approach

Guidance, not a script: apply it when a reported bug touches coordinates, canvas sizing, clicks, or UI state. The core lesson from real incidents this skill supports: **static analysis can prove that input↔render math is perfectly invertible, yet the app is still broken — because the browser breaks the mapping at the layout level.** Never conclude "the code is fine" from math alone; verify on a real running page.

## Test Pyramid for This Codebase

| Family | Tool | Notes |
|---|---|---|
| Pure logic — hit tests, `screenToWorld`/`sx`/`sy` consistency, rotation/AABB math, snap, codec round-trip | Vitest (environment `node`) | Cheap, fast, no DOM needed |
| DOM API smoke (not layout!) | Vitest + jsdom | jsdom **cannot** layout: `getBoundingClientRect` ≈ 0, no canvas rendering |
| Canvas sizing, DPR, window-resize races, click→selection, coordinate alignment | Playwright (or CDP) driving a **real browser** | The only layer that can reproduce "click on shape misses" bugs |

Rule of thumb: anything whose failure depends on `getBoundingClientRect`, devicePixelRatio, CSS layout, canvas bitmap size, or a real mouse event belongs to the real-browser row. jsdom will report green for bugs that only exist in a real browser.

## Workflow: Bug → Fix → Verified

1. **Hypothesize the mechanism** from the symptom; guess which of four layers owns it:
   - *Input conversion* — client → canvas logical → world (`mouseXY`/`screenToWorld` style code)
   - *Data* — what the store/array really holds (surprisingly often the culprit is a stale or mis-snapped value)
   - *Render* — where visuals are drawn (same transforms as input? rotated? center vs corner anchor?)
   - *Layout* — logical size vs bitmap size vs CSS box disagreeing (bitmap ≠ `rect.width/height` with different aspects ⇒ anisotropic click scaling)
2. **Reproduce on the real running page first** — script the browser (Playwright/`@playwright/test`, or a raw CDP client) and drive real mouse event chains. Assert the failure (red) before touching code.
3. **Sandwich-probe the layers** with temporary in-app instrumentation (expose the module's `store`/`view`/`screenToWorld`/`sx`/`sy` on `window`, log inside the hit handler). This separates "conversion wrong" from "data wrong" from "render wrong".
4. **Fix at the invariant, not the symptom.** Example invariants that kill whole bug classes:
   - Canvas: logical size = bitmap size = CSS box = container client size, re-synced on every frame (self-heal on mismatch), CSS box pinned via `cv.style.width/height` so replaced-element aspect-ratio tricks can't diverge.
   - Camera: on any canvas size change, recompute the old center with the **old** size, then re-center with the new size (never compute "old center" after mutating sizes — that's an identity NOP).
5. **Verify a matrix, not one case**: initial size, window resize, DPR ≠ 1, zoom. Each scenario must pass; record before/after.
6. **Remove temporary probes. Keep regression tests** in the appropriate pyramid row.

## Coordinate-Alignment Verification Recipe

This is the method that empirically located the "click above selects" bug class:

1. **Draw** via a mouse chain: `mousedown` → several stepped `mousemove`s → `mouseup`, on the real page.
2. **Ground truth A (state)**: read DOM that reflects real app state — inspector panel text, status bar counts, selection highlight. Never trust canvas pixels alone.
3. **Ground truth B (visuals)**: pixel-scan the canvas via `getImageData` (downsample into a brightness grid, threshold for stroke/fill cells) to find where the shape is actually drawn.
4. **Probe the selectable band**: click at fine increments across X and Y through the suspected region, recording first/last hit per axis. The hit band vs the visual band vs the data bounds must coincide.
5. **Read the band offsets**: a mismatch tells you the broken axis and its magnitude in pixels (convert back via `SZ` to world units).
6. **Confirm the culprit layer** with the in-app probe (e.g., log `wx/wy` inside the `mousedown` handler alongside the `view` snapshot — if `wx` contradicts `view.SL + mx/SZ`, the input scale (`VW / rect.width`) differs from 1 ⇒ layout mismatch).
7. **Re-run the identical probes after the fix** — the band must now match; also re-check at a second window size.

## Pitfalls

- **jsdom gives false confidence**: no layout, no canvas, no DPR — it will pass broken layout-dependent code.
- **CDP/Playwright synthetic mouse must not pan the view between probes.** If a miss-click starts a `pan` drag state and any `mousemove` arrives while it is armed, the camera drifts and the band measurements lie. Reset drag state between probes, or re-measure `view` per probe, or keep the mouse stationary between down/up.
- **Click-priority intercepts**: spawn points, checkpoints, and any "always wins" hit test will swallow probes near them. Either probe away from those zones, temporarily move them, or account for the priority in expectations.
- **Snap changes final data vs the drag preview**: after a draw, the committed rect is the *snapped* rect; expect bounds from the snapped data, not the raw drag extent.
- **Edge expectations need the hit-test pad**: with `pad` in world units, clicking "25px outside the edge" of a tall shape can still be inside `±(h/2 + pad·SZ)`. Compute the true miss distance before asserting.
- **Re-measure the canvas rect after window resizes**: `getBoundingClientRect` changes; a cached layout makes boundary probes fail for test reasons, not code reasons.
- **Pixel scans hit noise**: spawn markers, text labels, grid axes, and glows are bright too — scan midline rows/columns crossing the shape body and attribute edges by their stroke, or subtract a before/after frame.

## Output Contract

When asked to test or fix a bug, return:

1. Suspected mechanism and the owning layer (input/data/render/layout).
2. Reproduction evidence — before state (scripted, real browser, failing assertion).
3. The verification matrix — scenarios × result (pass/fail), with numbers.
4. The exact change and **why it is an invariant** rather than a patch.
5. What regression tests were kept (and in which pyramid row), or why none were kept.

Prefer the smallest correct change. Preserve render/hit/data separation; treat tolerance and click-priority as explicit design choices, never as silently-tuned fixes.
